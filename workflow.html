AI 工作流技术方案：从零散材料到庭审策略初稿

说明产品背后的技术路线：材料怎么进来、在哪里脱敏、每一步用什么模型、怎样避免 AI 编造法条、新证据进来后怎样回流重算。这份方案只讲技术路线，不在产品界面中单独呈现；产品里律师看到的是结果（时间线、证据链、证据目录、质证意见、不利点），以及每条结论的原文出处。

v1.0 · 2026-11-22 · 二组 · 配套：App Demo · 高保真原型 · 需求文档 PRD

一、总览：原件不出律所，云端只收脱敏文本，结论由律师签字

工作流分三个区域。绿色区域在律师电脑或律所服务器上运行，处理含真实姓名、证件号的原件；蓝色区域调用云端大模型，只接收脱敏后的文本；金色区域是律师复核，AI 的输出必须经律师采纳才会写入证据目录和策略报告。

本机 / 律所私有化

①材料接入PDF、扫描件、照片、聊天截图、录音、Excel 流水
②识别转写OCR 识别文字 · ASR 转写方言录音 · 解析 Excel 表格
③脱敏5 类敏感信息替换为代号，映射表只存本机
⑧法条 / 类案检索权威法规库 + 向量检索，只召回有出处的条文
⑩引用校验输出中的法条必须出现在检索结果里

云端大模型（只收脱敏文本）

④要素抽取主体、金额、日期、事件、文件形成时间
⑤时间线与冲突检测合并事件，标出陈述冲突、时间存疑
⑥争议焦点 + 证据链主张 ↔ 证据配对，找出缺口
⑦证据目录按证据链顺序编号、计算页码
⑨策略生成攻防路径 · 质证意见（三性）· 不利点排查 · 待补材料清单

律师复核

⑪核对与采纳逐条看原文出处，采纳 / 退回 / 修改
写回成果证据库、时间线、证据目录、策略报告
留痕记录模型版本、提示词、输出与采纳人
本机含个人信息的原文云端脱敏文本 + 结构化要素人工AI 不替律师下结论
触发 1：新建案件首批材料上传，跑完 ①–⑪，产出第一版时间线、证据链、目录和策略初稿。
触发 2：当事人补材料只对新材料跑 ①–④，再增量重算 ⑤–⑩，目录编号和页码自动重排。
触发 3：对方提交新证据走质证意见子流程（第四节），并重新评估受冲击的主张与攻防策略。

二、节点说明：每一步的输入、输出、模型和失败兜底

模型名称按 2026 年 10 月的公开资料整理，上线前需按厂商文档复核。所有云端调用都经过统一的模型网关（OpenAI 兼容协议），换模型只改配置。

节点输入 → 输出模型 / 组件位置失败兜底
① 材料接入各种格式文件 → 统一的「材料」记录（来源、上传轮次、文件哈希）文件服务；哈希去重本机重复文件或不同版本提示合并（问卷：处理重复材料是难点）
② 识别转写图片 / PDF → 带页码坐标的文字；录音 → 带时间戳的转写；Excel → 结构化流水PaddleOCR（开源）；本地 ASR 模型；表格解析本机置信度低于 0.85 的段落标黄，提示人工核对
③ 脱敏原文 → 脱敏文本 + 本机代号映射表正则规则 + Qwen3.8-27B 本地实体识别（Apache 2.0）本机规则与模型结果取并集，宁多勿漏；律师可逐类开关
④ 要素抽取脱敏文本 → JSON：当事人、金额、事件日期、文件形成日期、合同条款、证据来源DeepSeek V4.1-Flash（低成本、结构化输出）云端JSON 校验不通过自动重试 1 次，仍失败转人工
⑤ 时间线全部要素 → 按案件排序的事件节点，标「陈述冲突」「时间存疑」规则排序 + V4.1-Flash 合并同一事件云端日期无法确定时只标「存疑」，不猜日期
⑥ 争议焦点 + 证据链案情 + 要素 → 争议焦点、待证主张、主张 ↔ 证据对应、缺口bge-m3 向量相似度 + DeepSeek V4-Pro 判断云端每条对应附相似度与原文页码，低于阈值标「待确认」
⑦ 证据目录证据链 → 编号、名称、证明目的、页码确定性程序（不用大模型排版）本机新证据入库自动重排；保留历史版本可对比
⑧ 法条 / 类案检索争议焦点 → 法条原文、效力状态、类案裁判要旨权威法规库 + 向量库（RAG）私有化检索不到就明确写「未检索到」，不允许模型凭记忆补
⑨ 策略生成证据链 + 检索结果 → 攻防路径、质证意见、不利点、待补材料清单DeepSeek V4-Pro；备选 Kimi K3.1 Pro / GLM-5.3云端主模型超时 30 秒切备选模型；温度 0.2，强制 JSON
⑩ 引用校验生成结果 → 每条法条 / 类案是否命中检索结果规则引擎（文本匹配 + 条号比对）本机未命中的引用标红，并阻止写入报告
⑪ 律师复核AI 初稿 → 律师采纳 / 修改 / 退回—人工未经采纳的内容只显示为「AI 初稿」

三、回流机制：材料是多轮来的，成果要能自动跟着变

访谈里律师提到当事人很少一次交齐材料，问卷里律师说补材料后「页码的调整是最大的困难」。所以工作流不是一条直线，而是每来一批材料就增量重算一次。

新材料上传识别 + 脱敏（①–③）
→
增量抽取只处理新材料（④）
→
重算受影响部分时间线插入新节点，重新匹配证据链（⑤⑥）
→
重排目录编号和页码自动更新（⑦）
→
更新缺口重新生成待补材料清单发给当事人
↺ 清单发出 → 当事人补交 → 回到第一步。每一轮都保留版本，律师能看到这一轮新增了哪些证据、哪些主张从「需补强」变成「已具备」。

四、重点子流程：对方提交新证据 → 质证意见

这是访谈中律师认为最值得交给 AI 的环节：对方可能在举证期限最后一天提交大量新证据，需要快速围绕真实性、合法性、关联性写质证意见，并调整原有策略。

# 系统提示词（节选）
你是协助中国执业律师准备庭审的助手。
只能依据用户提供的证据材料和「可引用法条」作答，
不得编造法条、案例或事实；材料中的当事人信息
已脱敏，不要尝试还原。输出严格的 JSON。

# 用户提示词模板
【案件】{案件名}（{案由}，我方为{诉讼地位}）
【对方新证据】{编号} {名称}，提交日期 {日期}，
开庭日期 {日期}；证明目的：{证明目的}
证据原文（已脱敏）：{原文}
【我方相关证据】{证据链中对应主张的我方证据}
【可引用法条】{第⑧步检索结果，含原文}
请从真实性、合法性、关联性三方面给出质证意见。
# 输出 JSON 结构
{
  "真实性": {"结论": "无异议|有异议", "理由": "≤30字"},
  "合法性": {"结论": "...", "理由": "..."},
  "关联性": {"结论": "...", "理由": "..."},
  "质证意见": "可直接当庭发表的完整意见，≤220字",
  "引用法条": ["只能从可引用法条中选"],
  "受冲击的主张": ["借贷合意成立"],
  "策略调整建议": ["申请证人出庭接受询问"]
}

# 后处理
JSON 校验 → 引用校验（第⑩步）→ 标出原文页码
→ 律师采纳后写回证据库与策略报告

五、可信度设计：让律师「只需要核对」

访谈结论：AI 不能替律师担责，价值在于给出初稿让律师核对。所以每个输出都必须能快速核对。

防止编造

  • 只引用检索到的内容：法条、类案只能来自第⑧步检索结果，提示词中明确禁止凭记忆作答
  • 引用校验：输出里出现的每个条号都和检索结果比对，未命中的标红并拦截
  • 原文定位：每条事实、每个证据对应都带原文页码 / 录音时间戳，点开即见
  • 低温度 + 结构化输出：温度 0.2，强制 JSON，减少自由发挥

隐私与留痕

  • 数据分级：原件和代号映射表只在本机 / 律所服务器；云端只收脱敏文本
  • 不用于训练：与模型厂商约定调用数据不用于训练；需要时整条链路私有化部署
  • 调用留痕：记录模型名称、版本、提示词、输出、采纳人和时间
  • 合规：面向公众上线时，使用已完成生成式人工智能服务备案的模型与服务

六、模型选型

原则：按环节选模型，调用量大的环节用便宜模型，推理要求高的环节用强模型；含个人信息的环节只用可本地部署的开源模型。

环节首选备选选择理由
OCR / 录音转写PaddleOCR + 本地 ASR多模态模型读图（如 V4.1-Flash）原件含明文个人信息，必须在脱敏前处理，不出律所
敏感信息脱敏规则 + Qwen3.8-27B 本地规则 + 小型实体识别模型Apache 2.0 可商用，单机可运行
要素抽取 / 时间线DeepSeek V4.1-FlashGLM-5.3-Flash（MIT）调用量最大，需要便宜且结构化输出稳定
证据链 / 争议焦点bge-m3 向量 + DeepSeek V4-ProQwen3.8-Max先检索缩小范围再判断，控制长文本成本
质证意见 / 策略 / 不利点DeepSeek V4-ProKimi K3.1 Pro / GLM-5.3需要推理能力和长上下文；V4-Pro 为 MIT 许可，便于以后私有化
法条与类案权威法规库 + RAG对接北大法宝、威科先行等数据接口法律数据是行业壁垒，不让模型凭记忆写法条
模型版本、许可协议和价格变化很快：同一款模型的 API 价格在 2026 年内变动过多次。上线前需按厂商官网复核，并用同一套律师标注的测试集（如 50 份真实脱敏证据）比较各候选模型的准确率、耗时和成本后再定。

七、部署形态

MVP（课程演示 / 内测）

  • 前端：PWA 网页 App，手机「添加到主屏幕」即可安装；同一套代码出网页版
  • 后端：一台云服务器运行模型网关、文件服务、向量库
  • 模型：云端 API（经网关调用，前端不持有 Key）
  • 脱敏：在浏览器端 / 律所电脑完成后再上传

试点律所

  • OCR、ASR、脱敏、向量库部署在律所服务器
  • 大模型可选：云端 API（只收脱敏文本）或整体私有化部署开源模型
  • 法规库对接已授权的数据源
  • 账号体系：律所组织 → 律师 → 案件三级权限
本方案为课程作业技术路线说明，模型与价格信息来自 2026 年 10 月前后公开资料，需在实施前复核。
